## 💡 RAGFlow란?

[RAGFlow](https://ragflow.io/)는 최첨단 [RAG](https://ragflow.io/basics/what-is-rag)(Retrieval-Augmented Generation) 기술과 Agent 기능을 융합하여 대규모 언어 모델(LLM)을 위한 우수한 컨텍스트 계층을 구축하는 선도적인 오픈소스 RAG 엔진입니다. 모든 규모의 기업에 적용할 수 있는 간결한 RAG 워크플로를 제공하며, 통합 [컨텍스트 엔진](https://ragflow.io/basics/what-is-agent-context-engine)과 사전 구축된 Agent 템플릿을 통해 개발자가 복잡한 데이터를 탁월한 효율성과 정밀도로 고품질의 프로덕션 준비 완료 AI 시스템으로 변환할 수 있도록 지원합니다.

### 🍱 **템플릿 기반 청킹**

- 지능적이고 설명 가능한 방식.
- 다양한 템플릿 옵션을 제공합니다.

### 🌱 **할루시네이션을 줄인 근거 있는 인용**

- 텍스트 청킹을 시각화하여 사람이 개입할 수 있도록 합니다.
- 핵심 참고 자료를 빠르게 확인하고 추적 가능한 인용으로 근거 있는 답변을 지원합니다.

### 🍔 **다양한 데이터 소스와의 호환성**

- Word, 슬라이드, Excel, TXT, 이미지, 스캔본, 구조화된 데이터, 웹 페이지 등을 지원합니다.

### 🛀 **자동화되고 손쉬운 RAG 워크플로우**

- 개인과 대기업 모두에 맞춘 간결한 RAG 오케스트레이션.
- 구성 가능한 LLM 및 임베딩 모델.
- 다중 리콜과 결합된 융합 re-ranking.
- 비즈니스와 원활하게 통합할 수 있는 직관적인 API.

## 🎬 자체 호스팅

### 📝 사전 준비 사항

- CPU >= 4 cores
- RAM >= 16 GB
- Disk >= 50 GB
- Docker >= 24.0.0 & Docker Compose >= v2.26.1
- Python >= 3.13
- [gVisor](https://gvisor.dev/docs/user_guide/install/): RAGFlow의 코드 실행기(샌드박스) 기능을 사용하려는 경우에만 필요합니다.

> [!TIP]
> 로컬 머신(Windows, Mac, Linux)에 Docker가 설치되어 있지 않다면 [Docker Engine 설치](https://docs.docker.com/engine/install/)를 참조하세요.

### 🚀 서버 시작하기

1. `vm.max_map_count`가 262144 이상인지 확인하세요:

   > `vm.max_map_count`의 값을 확인하려면:
   >
   > ```bash
   > sysctl vm.max_map_count
   > ```
   >
   > `vm.max_map_count`가 262144보다 작다면 최소 262144로 재설정하세요.
   >
   > ```bash
   > # 이 예시에서는 262144로 설정합니다:
   > sudo sysctl -w vm.max_map_count=262144
   > ```
   >
   > 이 변경 사항은 시스템 재부팅 후 초기화됩니다. 변경 사항을 영구적으로 적용하려면 **/etc/sysctl.conf**에서 `vm.max_map_count` 값을 추가하거나 업데이트하세요:
   >
   > ```bash
   > vm.max_map_count=262144
   > ```
2. 저장소를 클론하세요:

   ```bash
   git clone https://github.com/infiniflow/ragflow.git
   ```
3. 미리 빌드된 Docker 이미지를 사용하여 서버를 시작하세요:

> [!CAUTION]
> 모든 Docker 이미지는 x86 플랫폼용으로 빌드되었습니다. 현재 ARM64용 Docker 이미지는 제공하지 않습니다.
> ARM64 플랫폼을 사용 중이라면 [이 가이드](https://ragflow.io/docs/dev/build_docker_image)를 따라 시스템과 호환되는 Docker 이미지를 빌드하세요.

> 아래 명령어는 RAGFlow Docker 이미지의 `v0.27.2` 에디션을 다운로드합니다. 다양한 RAGFlow 에디션에 대한 설명은 다음 표를 참조하세요. `v0.27.2`가 아닌 다른 에디션을 다운로드하려면 `docker compose`로 서버를 시작하기 전에 **docker/.env** 파일의 `RAGFLOW_IMAGE` 변수를 적절히 업데이트하세요.

```bash
   cd ragflow/docker

   git checkout v0.27.2
   # 선택 사항: 안정 버전 태그 사용 (릴리스 목록: https://github.com/infiniflow/ragflow/releases)
   # 이 단계는 코드의 entrypoint.sh 파일이 Docker 이미지 버전과 일치하도록 보장합니다.

   # DeepDoc 작업에 CPU 사용:
   docker compose -f docker-compose.yml up -d

   # DeepDoc 작업을 GPU로 가속하려면:
   # sed -i '1i DEVICE=gpu' .env
   # docker compose -f docker-compose.yml up -d
```

> 참고: `v0.22.0` 이전 버전에서는 임베딩 모델이 포함된 이미지와 임베딩 모델이 포함되지 않은 slim 이미지를 모두 제공했습니다. 자세한 내용은 다음과 같습니다:

| RAGFlow image tag | Image size (GB) | Has embedding models? | Stable?        |
|-------------------|-----------------|-----------------------|----------------|
| v0.21.1           | &approx;9       | ✔️                    | Stable release |
| v0.21.1-slim      | &approx;2       | ❌                     | Stable release |

> `v0.22.0`부터는 slim 에디션만 배포하며 이미지 태그에 **-slim** 접미사를 더 이상 붙이지 않습니다.

4. 서버가 시작된 후 서버 상태를 확인하세요:

   ```bash
   docker logs -f docker-ragflow-cpu-1
   ```

   _다음 출력은 시스템이 성공적으로 시작되었음을 확인합니다:_

   ```bash

         ____   ___    ______ ______ __
        / __ \ /   |  / ____// ____// /____  _      __
       / /_/ // /| | / / __ / /_   / // __ \| | /| / /
      / _, _// ___ |/ /_/ // __/  / // /_/ /| |/ |/ /
     /_/ |_|/_/  |_|\____//_/    /_/ \____/ |__/|__/

    * Running on all addresses (0.0.0.0)
   ```

   > 이 확인 단계를 건너뛰고 바로 RAGFlow에 로그인하면, 그 시점에 RAGFlow가 완전히 초기화되지 않았을 수 있으므로 브라우저에 `network abnormal` 오류가 표시될 수 있습니다.
   >
5. 웹 브라우저에 서버의 IP 주소를 입력하고 RAGFlow에 로그인하세요.

   > 기본 설정을 사용하는 경우 `http://IP_OF_YOUR_MACHINE`만 입력하면 됩니다(포트 번호 **제외**). 기본 구성에서는 기본 HTTP 서비스 포트 `80`을 생략할 수 있습니다.
   >
6. [service_conf.yaml.template](./docker/service_conf.yaml.template)에서 `user_default_llm`에 원하는 LLM 팩토리를 선택하고 `API_KEY` 필드를 해당 API 키로 업데이트하세요.

   > 자세한 내용은 [llm_api_key_setup](https://ragflow.io/docs/dev/llm_api_key_setup)을 참조하세요.
   >

   _이제 쇼가 시작됩니다!_

## 🔧 설정

시스템 설정과 관련하여 다음 파일들을 관리해야 합니다:

- [.env](./docker/.env): `SVR_HTTP_PORT`, `MYSQL_PASSWORD`, `MINIO_PASSWORD`와 같은 시스템의 기본 설정을 보관합니다.
- [service_conf.yaml.template](./docker/service_conf.yaml.template): 백엔드 서비스를 구성합니다. 이 파일의 환경 변수는 Docker 컨테이너가 시작될 때 자동으로 채워집니다. Docker 컨테이너 내에 설정된 모든 환경 변수를 사용할 수 있으므로 배포 환경에 따라 서비스 동작을 커스터마이즈할 수 있습니다.
- [docker-compose.yml](./docker/docker-compose.yml): 시스템은 [docker-compose.yml](./docker/docker-compose.yml)을 사용하여 시작됩니다.

> [./docker/README](./docker/README.md) 파일은 [service_conf.yaml.template](./docker/service_conf.yaml.template) 파일에서 `${ENV_VARS}`로 사용할 수 있는 환경 설정과 서비스 구성에 대한 자세한 설명을 제공합니다.

기본 HTTP 서비스 포트(80)를 변경하려면 [docker-compose.yml](./docker/docker-compose.yml)에서 `80:80`을 `<YOUR_SERVING_PORT>:80`으로 변경하세요.

위 설정을 변경한 후에는 모든 컨테이너를 재시작해야 적용됩니다:

> ```bash
> docker compose -f docker-compose.yml up -d
> ```

### Elasticsearch에서 Infinity로 문서 엔진 전환

RAGFlow는 기본적으로 Elasticsearch를 사용하여 전체 텍스트와 벡터를 저장합니다. [Infinity](https://github.com/infiniflow/infinity/)로 전환하려면 다음 단계를 따르세요:

1. 실행 중인 모든 컨테이너를 중지합니다:

   ```bash
   docker compose -f docker/docker-compose.yml down -v
   ```

> [!WARNING]
> `-v`는 Docker 컨테이너 볼륨을 삭제하며 기존 데이터가 모두 지워집니다.

2. **docker/.env**의 `DOC_ENGINE`을 `infinity`로 설정합니다.
3. 컨테이너를 시작합니다:

   ```bash
   docker compose -f docker/docker-compose.yml up -d
   ```

> [!WARNING]
> Linux/arm64 머신에서 Infinity로 전환하는 것은 아직 공식적으로 지원되지 않습니다.

## 🔧 Docker 이미지 빌드

이 이미지의 크기는 약 2 GB이며 외부 LLM 및 임베딩 서비스에 의존합니다.

```bash
git clone https://github.com/infiniflow/ragflow.git
cd ragflow/
docker build --platform linux/amd64 -f Dockerfile -t infiniflow/ragflow:nightly .
```

프록시 환경에 있는 경우 프록시 인수를 전달할 수 있습니다:

```bash
docker build --platform linux/amd64 \
  --build-arg http_proxy=http://YOUR_PROXY:PORT \
  --build-arg https_proxy=http://YOUR_PROXY:PORT \
  -f Dockerfile -t infiniflow/ragflow:nightly .
```

## 🔨 개발을 위해 소스 코드로 서비스 시작

> [!IMPORTANT]
> 저장소를 처음 클론한 후에는 로컬 Git 훅을 활성화하기 위해 저장소 루트에서 `git config --local --unset core.hooksPath`, `uv tool install lefthook`, `lefthook install`을 한 번 실행하세요.

1. `uv`를 설치합니다. 이미 설치되어 있다면 이 단계를 건너뛰세요:

   ```bash
   pipx install uv
   ```
2. 소스 코드를 클론하고 Python 의존성을 설치합니다:

   ```bash
   git clone https://github.com/infiniflow/ragflow.git
   cd ragflow/
   uv sync --python 3.13 # install RAGFlow dependent python modules
   uv run python3 ragflow_deps/download_deps.py
   git config --local --unset core.hooksPath
   uv tool install lefthook
   lefthook install
   ```
3. Docker Compose를 사용하여 의존 서비스(MinIO, Elasticsearch, Redis, MySQL)를 시작합니다:

   ```bash
   docker compose -f docker/docker-compose-base.yml up -d
   ```

   `/etc/hosts`에 다음 줄을 추가하여 **docker/.env**에 지정된 모든 호스트가 `127.0.0.1`로 해석되도록 합니다:

   ```text
   127.0.0.1       es01 infinity mysql minio redis sandbox-executor-manager
   ```
4. HuggingFace에 접근할 수 없는 경우 `HF_ENDPOINT` 환경 변수를 설정하여 미러 사이트를 사용하세요:

   ```bash
   export HF_ENDPOINT=https://hf-mirror.com
   ```
5. 운영 체제에 jemalloc이 없다면 다음과 같이 설치하세요:

   ```bash
   # Ubuntu
   sudo apt-get install libjemalloc-dev
   # CentOS
   sudo yum install jemalloc
   # OpenSUSE
   sudo zypper install jemalloc
   # macOS
   brew install jemalloc
   ```
6. 백엔드 서비스를 시작합니다:

   ```bash
   source .venv/bin/activate
   export PYTHONPATH=$(pwd)
   bash docker/launch_backend_service.sh
   ```
7. 프론트엔드 의존성을 설치합니다:

   ```bash
   cd web
   npm install
   ```
8. 프론트엔드 서비스를 시작합니다:

   ```bash
   npm run dev
   ```

   _다음 출력은 시스템이 성공적으로 시작되었음을 확인합니다:_

   ![RAGFlow web interface](https://github.com/user-attachments/assets/0daf462c-a24d-4496-a66f-92533534e187)
9. 개발이 완료되면 RAGFlow 프론트엔드 및 백엔드 서비스를 중지합니다:

   ```bash
   pkill -f "ragflow_server.py|task_executor.py"
   ```
